Enforcement model, stated honestly. Subscription = coach (soft levers): CLAUDE.md governance, usage-violation alerts, manager digest, skills sync — all plans. A determined dev can ignore the platform; enforcement is ultimately a manager conversation backed by undeniable data. API + proxy = enforce (hard levers): model routing rewrites the model field, daily budget returns a 429, context limit returns 413, key revocation is instant. Proxy is one env var (ANTHROPIC_BASE_URL), ~20–80ms latency, opt-in — enabled once trust is established. This is exactly why dedup guard and guardrails are SDK/proxy-only.

01·C

What the billing audit actually finds

Honest about likelihood and recoverability. The audit runs automatically; when it finds something it drafts a support ticket, and when it finds nothing, that confirmation is itself valuable.

Failed-request charges (5xx + billed)

Provider bills tokens on requests that returned an error. Proxy logs error + bill, cross-referenceable. A simple support ticket typically gets credit.

SometimesRecoverable

Wrong rate tier applied

Higher per-token rate than published — pricing changed mid-period, or volume discounts not applied. Provider usage API shows the model breakdown to verify.

SometimesRecoverable

Billing-period boundary double-charge

Month-end requests appear in two consecutive invoices. Proxy timestamps prove the correct period.

RareRecoverable

Token-count discrepancy

Invoice token count differs from response header. Extremely rare — both use the same server-side count, usually rounding. Worth flagging, rarely disputed successfully.

Very rareHard to prove

SLA uptime violations

Standard API plans have no SLA — no contractual obligation to credit downtime. Monitoring is still useful as evidence if you later negotiate a contract.

No contractNot recoverable

⚠ Honest positioning — don't oversell the standard tier

Standard API plan billing mismatches are real but small — typically 0.5–2% of spend. The support-ticket approach fits the size of issues found, so call it a "billing health check," not a "refund package." Significant recovery ($10k–$100k+) only becomes possible at the enterprise tier, because SLA contracts are what give you legal leverage. The output scales to what you can prove: standard teams get a support-ticket draft; enterprise teams get a legal-ready evidence bundle with a credit calculation.

02

The open gap — chat-based usage

Being honest about what we cannot reach today, so the roadmap doesn't promise coverage we can't deliver.

Unsolved · no known data access

We have no way to audit chat-based LLM usage

For interactive chat surfaces — ChatGPT web, Claude.ai, Gemini app, in-IDE chat on bundled plans — we do not currently have a path to the underlying usage data. There is no admin API, no exportable journal, and no billing line broken down per interaction. The flat fee is the only artifact, and it tells us nothing about rate or leakage.

This is a real constraint, not a sequencing choice. It stays out of the committed roadmap until a data path exists. The cards below are where a path might open — to be validated, not assumed.

Enterprise admin consoles

ChatGPT Enterprise / Claude Team sometimes expose seat-level usage analytics to admins. Worth probing whether any export exists.

→ research, unconfirmed

BYOK fallback

If a chat surface can be pointed at the customer's own API key, it collapses into the API tier and becomes auditable.

→ best available lever

Seat right-sizing only

Even with zero token data, headcount × plan tier × activity is auditable from procurement. Finding = seats, not rate.

→ partial, low-confidence

04·A

The conversion mechanic

Why the standard PLG move doesn't apply here, and what replaces it.

The mechanic flips. Normal PLG = "here's $X of waste, pay to recover it." We can't do that — the journal file has no rate data to find waste in. So instead: free surfaces the opportunities (what's likely leaking, observed from usage patterns), and paid implements the dedup + guard rules that actually act on them. Free shows the shape of the problem; paid applies the fix.

The sequencing logic in one line

Monday ships the journal logger + private SDK + fixed onboarding — observe-first, with the SDK as the enforcement-ready spine. The gate is the must-fix list: reconciliation is the keystone (it unblocks two violation types), the public-SDK ingestion bug has to be cleared, and the six silent violations verified for the refund report.
